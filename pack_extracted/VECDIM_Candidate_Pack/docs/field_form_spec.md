# Field form specification (entomology module)

The field worker enters the fields below. Everything else in the dataset is added by the server (satellite and climate layers) or comes from health-facility data, so it is **not** on the form.

## Fields entered on the device

| Field | Input | Rules |
| --- | --- | --- |
| `record_id` | Generated by the app (UUID v4) when the form is opened, never typed | Must be created offline. It stays the same through drafts, saving, syncing and resubmission. It makes uploads safe to repeat (idempotent) |
| `state` | Pick one: Lagos, Kano, Osun | Required |
| `lga` | Pick one, filtered by state (list below) | Required |
| `ward` | Pick one: "<LGA> Ward 1" to "<LGA> Ward 6" | Required |
| `latitude`, `longitude` | Captured automatically from device GPS, shown to the user, with a "recapture" button | Required. Subject to the GPS rules in `validation_rules.md` |
| `gps_accuracy_m` | The accuracy radius (metres) of the GPS fix, captured with the coordinates. Read-only, shown next to the coordinates | Required (automatic). Target 10 m or better; see "GPS capture" below |
| `collection_date` | Date picker, defaults to today | Required. Cannot be in the future |
| `species` | Pick one: An. gambiae s.s., An. coluzzii, An. arabiensis, An. funestus | Required |
| `insecticide` | Pick one: Permethrin, Deltamethrin, Alphacypermethrin, Pirimiphos-methyl | Required |
| `n_exposed` | Whole number, 1 to 500 | Required |
| `n_dead` | Whole number, 0 to `n_exposed` | Required |
| `mortality_pct` | Calculated: 100 x `n_dead` / `n_exposed`, rounded to 1 decimal. Read-only | Shown live. Show the WHO class next to it: below 90.0 Resistant, 90.0 up to but not including 98.0 Possible resistance, 98.0 and above Susceptible (see `validation_rules.md` for edge cases) |
| `larval_density` | Whole number, 0 or more (larvae per dip) | Required |
| `urban` | Toggle (0 or 1) | Required |
| `irs_covered` | Toggle: indoor residual spraying in the last 12 months | Required |
| `itn_use_pct` | Number 0 to 100 (households reporting bed-net use) | Required |

## LGAs and wards

| State | LGAs |
| --- | --- |
| Lagos | Ikorodu, Alimosho, Epe, Badagry, Eti-Osa |
| Kano | Dala, Nasarawa, Gwale, Tarauni, Ungogo |
| Osun | Osogbo, Ife Central, Ilesa East, Iwo, Ede North |

Reference points for the LGAs are in `data/lga_reference.csv`.

## GPS capture

- Ask the phone for its most accurate fix and show the live accuracy ("Accuracy: 7 m") next to the coordinates.
- **10 m or better:** accept the fix.
- **Above 10 m:** keep trying for up to 60 seconds and show "Waiting for a better GPS signal. Move to open sky." The user can recapture at any time. If the fix is still worse than 10 m, the user may continue; the record is saved with the `GPS_accuracy_poor` warning.
- **Above 50 m, or no accuracy value from the phone:** the record cannot be saved (`GPS_accuracy_unusable`). Tell the user to move to open sky and recapture.
- **Wrong place:** if the point is more than 25 km from the chosen LGA, warn the user before saving (`GPS_far_from_lga`) so they can correct the LGA or recapture. If the point is outside the chosen state or Nigeria, it is blocked (see `validation_rules.md`).

## Partly filled forms (drafts and recovery)

Field workers lose connection, battery and apps. A form that is half filled must not be lost.

- **Autosave.** While a form is open, the app saves it to local storage as a `draft` automatically: after each field change (a short delay of up to 2 seconds is fine) and whenever the app goes to the background. No Save tap is needed.
- **No blocking on drafts.** A draft may contain errors or empty required fields. The Block rules run only when the user taps Save.
- **Recovery.** If the app was closed unexpectedly, killed, or the phone restarted, the next time the app opens it offers to resume the draft ("You have an unfinished record from 14:32. Resume or discard?"). Resuming restores every value already entered, including the `record_id`, the GPS fix and the calculated values.
- **Drafts never sync.** Only a record the user has saved (and that passed the Block rules) goes to the sync queue. Saving a draft turns it into a `pending_sync` record and removes the draft.
- **Discarding.** The user can discard a draft, after confirming.
- Several drafts at once (a list of drafts) is a nice-to-have; one draft per user is the minimum.

## Added by the server (not on the form)

`rainfall_mm`, `temp_c`, `ndvi`, `elevation_m`, `dist_water_km` and `slide_positivity_pct`. In this task the seed data supplies them. New records from the app arrive without them, and that is not an error. The API should store them as null and mark the record `enrichment_pending`.

## Statuses a record can have on the device

| Status | Meaning |
| --- | --- |
| `draft` | Partly filled form, saved automatically. Not in the sync queue |
| `pending_sync` | Saved offline, waiting for a connection (or being retried) |
| `synced` | Accepted by the server |
| `synced_with_flags` | Accepted, but a Warn rule fired. Show the warning |
| `rejected` | The server refused it. The record stays on the device with the server's error messages. See below |

## Rejected records: fix and resubmit

When a batch comes back with some records rejected:

- Records the server accepted are marked `synced` or `synced_with_flags` and are **not** held back by the rejected ones.
- Each rejected record stays on the device, marked `rejected`, with the server's messages in plain language, for example "n_dead (120) is more than n_exposed (100). Correct the number of dead mosquitoes", and the field each message refers to.
- The user opens the record, sees the messages beside the fields they concern, changes only what is wrong, and taps Resubmit. All the other values are kept; nothing is entered again.
- A resubmitted record keeps its `record_id`, goes back to `pending_sync`, and is validated again by the app and the server. Repeat until accepted.
- A rejected record is never deleted automatically. A list or filter of "Needs attention" records is expected on the Field view.
